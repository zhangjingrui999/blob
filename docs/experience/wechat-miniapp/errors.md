# 微信小程序错误定位与兼容排查

错误码必须和接口、产品、基础库及完整错误消息一起解释。小程序、公众号、支付和云开发的数字码不能合成一张无上下文的通用对照表。

## 排查流程

1. 记录 API 名称、errMsg/errCode、请求标识、时间和可复现步骤，日志脱敏。
2. 分别检查网络与合法域名、登录态、权限、参数和业务返回。
3. 对照同一产品和接口的官方错误定义，识别可重试与永久失败。
4. 在开发者工具及真机复现，记录基础库、微信客户端和渲染模式。

开发工具关闭域名校验后成功不能证明上线可用。重试使用次数上限与退避，并确保业务幂等；无效凭证应按登录流程刷新，不无限循环调用。

## 遮罩与滚动

弹层背景滚动问题应检查滚动容器、触摸事件传播和组件支持。使用有明确作用范围的 catch 处理与状态切换，不把全局禁止所有触摸作为通用方案。

### 版本变化与兼容

| 范围              | 差异                   | 方案                                           |
| ----------------- | ---------------------- | ---------------------------------------------- |
| 基础库            | API 和组件属性逐步加入 | wx.canIUse + 失败路径，记录实测版本            |
| 开发者工具 / 真机 | 行为可能不同           | 发布前覆盖真机与最低支持环境                   |
| 旧错误码汇总      | 缺少产品和接口边界     | 按接口记录故障；未核实条目不继续当有效知识发布 |

依据：[官方 API 声明](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)、[兼容性文档入口](https://developers.weixin.qq.com/miniprogram/dev/framework/compatibility.html)。具体平台政策与错误码以可访问的对应接口文档为准。
