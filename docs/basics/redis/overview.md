# Redis 数据结构、缓存设计与一致性

Redis 是支持多种数据结构的服务。选型不仅看命令速度，还要考虑内存容量、数据恢复、并发一致性和故障边界。

## 数据结构选择

| 结构             | 常见用途            | 关键边界                   |
| ---------------- | ------------------- | -------------------------- |
| String           | 缓存、计数器        | 数值操作要求值可解析       |
| Hash             | 对象字段            | 不适合无限扩大的单个对象   |
| List             | 有序序列、简单队列  | 弹出后需应用设计确认与恢复 |
| Set / Sorted Set | 去重、关系 / 排行榜 | 大集合遍历与聚合成本       |
| Stream           | 消息日志、消费者组  | 需确认、重试、清理和幂等   |

## 缓存与并发

Cache-aside 通常先读缓存，未命中读数据库再回填；更新数据库后使缓存失效，但仍需分析并发读写窗口。使用合理 TTL、随机抖动与热点重建控制，防止穿透和集中失效压垮数据库。配置 maxmemory 与淘汰策略，并监控命中率、延迟、内存和逐出量。

分布式锁至少要原子获取、唯一所有者标记、超时和原子校验释放；租约过期后旧持有者仍可能继续运行，关键写入需要 fencing 或数据库约束。不能仅凭 SETNX 就宣称强一致。

### 版本变化与兼容

| 版本 | 能力变化      | 方案                                                |
| ---- | ------------- | --------------------------------------------------- |
| 5.0  | Streams       | 需要可靠消费时评估消费者组，不把 Pub/Sub 当持久队列 |
| 6.0  | ACL、RESP3    | 客户端与服务端协商协议，账号权限按最小范围配置      |
| 7.4  | Hash 字段过期 | 更低版本用独立键或业务清理策略；注意语义差异        |
