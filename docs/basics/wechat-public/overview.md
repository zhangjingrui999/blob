# 微信公众号消息链路、令牌与菜单

公众号服务器接入处理的是微信到业务服务端的消息链路。接入 Token、接口 access_token 与用户网页授权令牌用途不同，不能混用。

## 消息链路

用户操作经微信服务器转发到配置的服务端入口；服务端验证来源、解析消息，执行对应业务并按协议响应。对重复投递设计幂等，耗时任务与及时响应分离。加密模式还需验签、解密与接收方校验，不能只校验 URL 参数。

## 令牌与菜单

AppSecret 与令牌保存在服务端，access_token 按实际返回有效期统一缓存和刷新，防止多个实例互相覆盖。接口失败记录请求标识，避免无条件重复刷新令牌。

菜单配置先确定当前账号具有的接口权限，按按钮类型填写字段；后台人工菜单与 API 管理菜单的行为需要核对。字符长度和菜单数量限制以对应官方页面为准，不用旧笔记“显示省略号”的描述替代接口校验。

### 版本变化与兼容

| 范围          | 历史问题                       | 当前方案                                   |
| ------------- | ------------------------------ | ------------------------------------------ |
| 产品分类      | 企业号被简单列为一种现行公众号 | 公众号与企业微信分开查阅产品文档           |
| 接口权限      | 受账号类型、认证和政策影响     | 在后台与当前接口文档确认，不写固定权限矩阵 |
| 明文/加密模式 | 处理协议不同                   | 使用匹配模式的验签与加解密流程             |
